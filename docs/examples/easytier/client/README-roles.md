# 两个人的傻瓜式分工（谁导入哪份 ✓）

**目标** ✓：**A 的国外流量，从 B 的线路出去** ✓ —— 双方**只装 Clash + 导入一份订阅** ✓。

| 你是 | 导入哪份 | 你要从对方拿到什么 | 你要给对方什么 |
| --- | --- | --- | --- |
| **A · 借出口**（想出国的那台 ✓） | [`subscription-borrow.yaml`](subscription-borrow.yaml) | **B 的 overlay 地址**（如 `10.144.0.6` ✓） | `网络名` / `密钥` / `会合点` ✓ |
| **B · 提供出口**（线路好的那台 ✓） | [`subscription-provide.yaml`](subscription-provide.yaml) | `网络名` / `密钥` / `会合点` ✓ | **你自己的 overlay 地址** ✓（在配置里自己填 ✓，固定唯一 ✓） |

**双方共同的三项** ✓（必须一字不差 ✓）：`network-name` ✓、`network-secret` ✓、`peers`（会合点 ✓）。

**建立顺序** ✓（先 B 后 A ✓）：B 先导入并生效 ✓（它一起床就在网里 ✓）→ A 再导入 ✓ → A 选中「🌍 走朋友的出口」这个策略组 ✓ → 打开 google 验证 ✓。

**共同的三条坑** ✗✓（都在模板里写好了 ✓）：
1. **回环防护规则必须最前** ✓ —— 否则"实例 running 但进不了网" ✓（本机自己的 TUN 把 overlay 网段抓走了 ✓）；
2. **`prewarm: true` 不能省** ✓ —— 省了实例不会被拉起 ✓，对方在 overlay 里看不到你 ✓；
3. **国外域名解析要走出口那条线** ✓（`nameserver-policy` 里的 `#et-exit` ✓）—— 否则国内 DNS 给你**污染 IP** ✓，出口方照着假 IP 连 → 超时 ✓。
